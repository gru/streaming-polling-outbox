## 12. PostgreSQL WAL Retention

Настрой `max_slot_wal_keep_size` корректно, исходя из фактического объёма генерируемого WAL, а не размера пользовательских сообщений.

### 12.1 Нормальная эксплуатация

- По умолчанию используй `max_slot_wal_keep_size = -1` (без ограничения удержания WAL replication slot).
- Обеспечь мониторинг объёма удерживаемого WAL, чтобы избежать неконтролируемого заполнения диска.
- Контролируй `restart_lsn`, `confirmed_flush_lsn`, `wal_status`, `safe_wal_size` и текущую WAL LSN.
- При длительной недоступности Kafka CDC не должен подтверждать LSN, пока сообщения не доставлены.
- Настрой мониторинг свободного дискового пространства PostgreSQL.

### 12.2 Отдельный WAL Pressure Test

Для исследования поведения при нехватке WAL реализуй отдельный тест с ограниченным `max_slot_wal_keep_size`.

Размер ограничения должен рассчитываться относительно **фактически измеренного объёма WAL**, а не объёма JSON payload.

Сценарий:

1. Измерь количество WAL, генерируемого Writer при заданной нагрузке, через разницу WAL LSN.
2. Выбери значение `max_slot_wal_keep_size`, равное приблизительно 50% измеренного объёма WAL.
3. Примени конфигурацию PostgreSQL и проверь её фактическое значение.
4. Останови Kafka, продолжая запись сообщений Writer.
5. Проверь рост удерживаемого WAL и состояние logical replication slot.
6. При необходимости инициируй checkpoint для проверки применения ограничения.
7. Проверь обнаружение инвалидированного слота CDC-сервисом.
8. Убедись, что сервис не скрывает потерю WAL и не заявляет об успешной доставке потерянных сообщений.

Учитывай, что `max_slot_wal_keep_size` применяется при checkpoint, не является строгим мгновенным лимитом и не гарантирует инвалидизацию слота при каждом запуске теста.

### 12.3 Критерии приёмки

- В обычных тестах failover, switchover и Kafka outage необходимые WAL сохраняются.
- В WAL Pressure Test проверяется поведение при ограничении удержания WAL.
- Инвалидированный слот обнаруживается и диагностируется.
- Автоматическое пересоздание слота с пропуском сообщений запрещено.
- Результаты WAL Pressure Test не используются как доказательство выполнения гарантии `at-least-once` после утраты WAL.

Также удали из раздела 22 (RISK-006) любые формулировки, связывающие лимит WAL с размером payload. Ограничение должно рассчитываться по фактическому WAL.
